# 设计文档：井下人员定位安全系统

## 1. 背景与目标

井下作业的高风险点集中在两类：**人进入了不该进的区域**（变电所、采空区、瓦斯异常巷），以及**人在某处失去行动能力但无人知晓**（晕倒、负伤、被困）。传统带班清点和巡检是事后的、离散的；UWB 定位能以亚米级精度持续给出每名井下人员的三维坐标，使安全规则可以被机器持续执行。

系统目标：

1. 接收 UWB 定位引擎上报的人员坐标并持久化（事后可追责）；
2. 对每条位置实时执行安全规则，命中即生成**分级告警**；
3. 告警自动联动**分区语音广播**，形成对当事人的直接干预；
4. 给调度室提供实时大屏、告警处置闭环、历史轨迹与统计。

非目标：不做考勤、工资、人员编制管理；不替代瓦斯监测监控系统（但可与其广播系统共用音箱）。

定位接入、规则判定在 API 请求路径上**同步**完成——安全判定不能排队等异步消费者，延迟必须可预测。worker 只承担与单条位置无关的周期任务（离线、对账、升级），独立进程保证接入高峰不会饿死安全扫描。

## 3. 数据模型

- **Person**：与 UWB 标签一一对应，主键即 `tagId`；冗余 `lastPos/lastSeenAt/batteryPct/status` 做大屏快照，避免每次聚合大位置表。
- **Position**：追加写入的原始定位（BigInt 自增主键，`(personId, measuredAt)` 索引），保存的是**标签测量时间**而非入库时间，用于轨迹回放与事后分析。
- **Zone**：多边形顶点 JSON（矿井局部坐标，米）+ `floor` 所在水平 + 危险级别 + 音箱分组 + TTS 模板。
- **Alarm**：`type/severity/status/dedupKey/repeatCount/firstFiredAt/lastFiredAt/ackedAt/resolvedAt/escalatedAt`。
- **Broadcast**：每次喊话（自动或手动）必留痕：分组、内容、下发状态、失败原因。
- **IngestKey**：与用户体系隔离的设备凭证，泄露后可单独吊销。

### 3.1 去重不变量

```sql
CREATE UNIQUE INDEX alarm_open_dedup_uniq
  ON "Alarm"("dedupKey")
  WHERE status IN ('active','acked');
```

任意时刻，同一 `dedupKey`（如 `zone_intrusion:TAG-003:<zoneId>`）至多存在一条未解除告警。这是安全相关的不变量，因此用**数据库约束**而非应用层检查实现：两批定位并发判出同一事件时，一个 INSERT 成功，另一个收到 P2002 后转为 `repeatCount+1`。

> 该部分唯一索引写在迁移 SQL 中，Prisma schema 无法表达，勿用 `prisma migrate diff` 覆盖（会判为多余索引并 DROP）。

## 4. 规则引擎

### 4.1 电子围栏

- 射线法点在多边形内，**边界点按进入处理**（压线不能漏报）；
- 先按 `|zone.floor - z| ≤ 5m` 过滤水平，跨层不判定（竖井/斜坡道场景）；
- `safe` 区域只展示不告警；
- 进入 → 按区域级别产生 critical/warning 告警并联动该区域分组广播；
- 持续在区域内 → 抑制窗口（默认 300s）内只累加 `repeatCount`，窗口外重复喊话一次（长时间滞留提醒）；
- 离开 → 自动解除。在区域内的状态集合保存在进程内存，worker 定时用数据库快照**对账**（进程重启后有人离开也能补上解除）。

### 4.2 长时间静止（锚点簇算法）

不能用"相邻两点距离"判定——静止人员的 UWB 坐标存在 0.1~0.5m 的随机抖动，会被误判为持续移动。算法：

1. 维护一个锚点：每个新点与锚点的 3D 距离 ≤ `radiusM`（默认 3m）则并入簇；
2. 超出半径则以该点重建锚点（人确实移动了）；
3. 只考察**延续到最新点**的簇：簇首到当前时间 ≥ `afterSec`（默认 120s）判静止。

历史上的静止段（人已经走开）不触发告警。垂直方向计入距离（斜坡/竖井内上下移动也算移动）。恢复移动自动解除并把人员状态改回 active。

### 4.3 其他规则

- **SOS**：标签按键上报，critical + 全矿广播；**只能人工解除**。
- **低电量**：≤15% 产生 info 提示，恢复到 ≥20% 才解除（5% 迟滞，阈值附近抖动不反复告警）；不广播。
- **离线**：worker 扫描 `lastSeenAt` 超过 90s 的在籍标签，置 offline + warning；重新收到位置自动解除。
- **超时升级**：active 的 **warning** 告警超过 300s 未确认 → critical 并全矿广播一次提醒。info 不升级（低电量喊话是噪音）。

### 4.4 告警处置状态机

```
                自动命中                 调度确认            现场核实
  (无) ───────────────────► active ──────────────► acked ──────────────► resolved
   ▲                          │  ▲                    │                     ▲
   │                          │  │ 持续触发退回 active  │                     │
   │      自动解除（离开/恢复/上线）└────────────────────┘            调度员手工解除（SOS 唯一出口）
   └──────────────────────────┴─────────────────────────────────────────────┘
```

## 5. 广播联动

- 驱动可插拔：`console`（开发/无硬件，日志输出）与 `webhook`（POST 矿上 IP 广播主机 `{group,text}`）。
- 自动喊话类型白名单：闯入 / 静止 / SOS；低电量、离线不喊。
- 分区：区域配 `speakerGroup`，只喊该区域音箱；SOS 与升级提醒全矿。
- TTS 模板支持 `{name} {team} {zone}`。
- 每次下发落库；webhook 超时（默认 5s）/非 2xx 标记 failed，界面可重发。

## 6. 实时通道

`GET /ws`（单实例内存连接表；多实例需前置粘性会话或加 Redis pub/sub）。事件：

```jsonc
{ "type": "positions", "data": [{ "tagId", "x","y","z","batteryPct","t","sos" }] }
{ "type": "alarm",     "data": { /* Alarm 全字段，含状态变化 */ } }
{ "type": "broadcast", "data": { /* Broadcast 留痕 */ } }
{ "type": "person",    "data": { "tagId", "status" } }
```

前端断线 3s 自动重连；首屏用 REST snapshot 兜底。

## 8. 安全与可靠性

- 设备接入与用户 JWT 双轨凭证；登录限流 + bcrypt 12 轮 + 用户名不存在时也执行一次比较防枚举；helmet/CORS 白名单。
- 位置数据与规则副作用解耦：先 `createMany` 落位置（证据），再做告警/广播；后者失败不影响位置入库。
- 未登记/停用标签、非法坐标、未来时间戳一律拒绝且不落库。
- 关键不变量（未决告警唯一）由数据库保证；PGlite 集成测试中以 `Promise.all` 并发触发验证。
- 广播"喊没喊出去"全程留痕可追溯。

## 9. 可配置阈值（环境变量）

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `PERSON_OFFLINE_AFTER_SEC` | 90 | 离线判定时长 |
| `STATIONARY_RADIUS_M` / `STATIONARY_AFTER_SEC` | 3 / 120 | 静止半径与持续时长 |
| `ALARM_DEDUP_WINDOW_SEC` | 300 | 重复触发重新广播的抑制窗口 |
| `ALARM_ESCALATE_AFTER_SEC` | 300 | 未确认升级时长 |
| `LOW_BATTERY_PERCENT` | 15 | 低电量阈值（恢复 +5%） |
| `BROADCAST_DRIVER` / `BROADCAST_WEBHOOK_URL` | console | 广播驱动 |
| `SCAN_INTERVAL_SEC` | 10 | worker 扫描周期 |

## 10. 测试策略

- **纯函数单测**：几何判定、静止算法、TTS 模板；
- **真实数据库集成测试**：PGlite（WASM PostgreSQL）执行**真实迁移 SQL**，验证约束（含部分唯一索引）与全规则闭环；阈值通过测试注入缩短，无需真实等待；
- **HTTP 端到端**：随机端口起完整 Express 应用，覆盖鉴权、RBAC、422、设备接入、告警处置闭环、广播留痕。
