# 架构与部署说明

## 模块划分

```
src/
├── server.js      进程入口：装配组件、HTTP 路由、检测主循环(setInterval 1s)、优雅退出
├── config.js      环境变量配置（全部参数有默认值，面向开箱演示）
├── defaults.js    矿井底图：巷道折线、危险区域多边形、人员档案
├── uwb.js         UWB 接入：UDP dgram 收 JSON 数据报，坏包统计丢弃
├── simulator.js   内置定位模拟源：9 名人员沿巷道巡逻 + 三个演练场景
├── store.js       PositionStore：标签运行时态、轨迹缓冲、告警/广播记录、JSON 落盘
├── geo.js         纯几何函数：射线法点在多边形内、点线距、位置语义标签、静止判定
├── detection.js   DetectionEngine：tick(now) 推进一个检测周期（无定时器，可单测）
├── broadcaster.js Broadcaster：console / sse / webhook 三渠道，话术拼装与失败重试
├── sse.js         SseHub：SSE 客户端管理、心跳、事件广播
└── snapshot.js    buildSnapshot：组装大屏全量帧
public/
├── index.html     三栏调度大屏（人员 / 地图 / 告警）
├── app.js         SSE 订阅、Canvas 渲染、WebAudio 警笛、Web Speech 播报
└── styles.css
```

## 检测周期数据流（每秒一次）

1. `runDetectionCycle()` 取 `Date.now()` 调 `engine.tick(now)`。
2. 引擎遍历每个标签：
   - 计算信号年龄 → 置/清 `offline`；
   - 在线标签计算当前所在**启用中**区域集合，与上一周期集合做差集 → 新进入即触发 `zone_entry`；
   - 更新停留计时器（偏离锚点 > 半径则清零），越过阈值触发 `stationary`；
   - 超过离线阈值触发 `offline`。
3. 扫描全部活动告警：
   - 消除条件满足 → `resolved` + 原因；
   - 高危且未确认且到点 → 重复广播。
4. tick 返回本周期事件列表（`alarm.raised/resolved`、`broadcast.sent`），主循环逐个推 SSE，并补一帧全量 `tick` 快照。

设计要点：**检测引擎本身不碰定时器与网络**，`tick(now)` 是纯推进函数；单元测试可以精确构造任意时间线（连续喂坐标后跳到 N 秒后）。

## 告警对象

```jsonc
{
  "id": "AL20260919141611-0001",
  "type": "zone_entry | stationary | offline",
  "tagId": "T002",
  "workerName": "王海涛",
  "zoneId": "zone-goaf",
  "zoneName": "1101 采空区",
  "level": "danger | warning",
  "status": "active | resolved",
  "raisedAt": 1789827000000,
  "resolvedAt": null,
  "resolveReason": null,
  "ackedAt": null,
  "ackedBy": null,
  "lastBroadcastAt": 1789827000000,
  "dwellSec": 0,          // stationary 专用
  "offlineSec": 15,       // offline 专用
  "x": 60.0, "y": 165.0   // 告警时刻坐标，事后可还原现场
}
```

去重键：`status=active + tagId + type (+ zoneId)`。同一区域停留期间不会重复建警；从 A 区离开后再进入会产生新告警。

## SSE 事件

| event | 时机 |
| --- | --- |
| `snapshot` | 连接建立，全量首帧（含历史告警与广播） |
| `tick` | 每个检测周期（默认 1s），全量轻量帧 |
| `alarm.raised` / `alarm.resolved` / `alarm.updated` | 告警增量 |
| `broadcast.sent` | 一次广播发出（前端据此响警笛/语音） |
| `simulator` | 演练场景切换 |
| `: ping` | 15s 心跳注释帧 |

EventSource 断线浏览器自动重连，重连后由新的 `snapshot` 帧对账，增量帧丢失不会造成状态不一致。

## 性能与容量

- 标签轨迹内存环形缓冲，每标签 180 点（1Hz 约 3 分钟），千人规模内存占用约几十 MB。
- 检测为 O(标签数 × 区域顶点数)；多边形顶点一般 < 50，单周期亚毫秒级。
- UDP 单数据报处理在消息回调内完成，无共享锁；存储为单进程模型。

## 从演示走向生产的改造清单

1. **坐标系标定**：UWB 引擎坐标 → 矿图坐标的换算在引擎侧完成，录入真实巷道与围栏顶点替换 `defaults.js`。
2. **持久化**：`data/state.json` 替换为 PostgreSQL/Redis；告警与广播记录按安监制度保留（通常 ≥ 3 个月）。
3. **鉴权**：当前接口无认证（井下专网假设）；接入办公网时为 ack/clear/PATCH/场景接口加调度员认证与操作审计。
4. **广播主机对接**：在 `Broadcaster` 增加 SDK 渠道（海康/世邦等 IP 广播的分区播放接口），按告警区域选择广播分区，而不是全井广播。
5. **多进程/双机**：检测引擎改为单活（Redis leader 锁），API 可多副本；告警去重与重复广播节奏依赖单活引擎。
6. **标签档案与考勤联动**：入井/升井事件用于清除标签态、统计井下人数；当前以"是否曾上报"近似。
