# 井下人员定位安全系统

基于 **UWB 超宽带定位坐标**的井下人员安全监控：人员进入危险区域（采空区、盲巷、带电硐室等）或长时间静止不动时自动告警，并**联动应急广播**（井下 IP 广播主机 / 调度平台 / 调度大屏语音警笛）。

零运行时依赖，Node.js ≥ 20 即可运行；前端为原生 Canvas 大屏，无需构建。

## 安全闭环

```
 UWB 定位引擎 ──UDP/JSON──▶ 接入层 ──▶ 位置存储（轨迹/停留计时）
                                              │
                                   每秒检测循环（纯状态机）
                              ┌───────────────┼────────────────┐
                              ▼               ▼                ▼
                        电子围栏闯入      长时间静止         信号丢失
                       （危险/警告分级）  （区域内升高危）   （搜寻通报）
                              │               │                │
                              └───────────────┼────────────────┘
                                              ▼
                                    告警生命周期管理
                        首次广播 → 未确认按节奏重复 → 确认静音
                                              │
              ┌───────────────────────────────┼────────────────────────┐
              ▼                               ▼                        ▼
      IP 广播主机(webhook)            调度大屏(sse+语音+警笛)     控制台声光
                                              │
              人员离开 / 恢复活动 / 信号恢复 ──▶ 自动解除（或调度员人工解除）
```

## 快速开始

```bash
cd mine-safety
npm start                 # 默认开启模拟源，打开 http://localhost:8090
```

| **闯入采空区** | 王海涛进入 1101 采空区 → 高危告警 + 警笛语音，每 20s 重复广播 |

接入真实定位引擎时关闭模拟源：

```bash
SIMULATOR_ENABLED=false UWB_UDP_PORT=5005 npm start
```

## UWB 接入协议

定位引擎解算出标签平面坐标后，向服务端 UDP 端口发送 JSON 数据报（一报一签，也支持批量）：

```json
{"tagId":"T001","x":12.40,"y":88.13,"z":0.0,"ts":1716000000000}
```

```json
{"positions":[{"tagId":"T001","x":12.4,"y":88.1,"z":0}, {"tagId":"T002","x":50.2,"y":96.7}]}
```

- 坐标为 UWB 引擎输出的**局部平面直角坐标（米）**，与大屏底图、围栏多边形同一坐标系。
- `ts` 可选（毫秒），缺省用接收时刻。
- 未建档标签不会被丢弃：自动以"未知标签"接住并参与全部检测——不能因为没建档就漏掉井下活人。
- 坏报文计入 `badDatagrams` 统计后丢弃，不影响监控循环。
- 也可使用 `POST /api/positions`（HTTP JSON，字段相同）对接不支持 UDP 的引擎。

## 检测规则（关键工程决策）

1. **围栏判定用射线法**，支持凹多边形（采空区边界常不规则），贴边点按区域内处理——边界上的人不能漏警。围栏可随时停用（检修/围栏施工），停用后立即不产生新告警。
2. **静止判定是"停留计时器 + 位移锚点"**：位置偏离锚点超过 `STATIONARY_RADIUS_M` 即清零重新计时。UWB 0.2~0.3m 的测量抖动不会误清零；正常步速 0.8m/s 走出 1.5m 只需约 2 秒，恢复判定及时。
   - 安全巷道内静止 → `warning`（可能只是休息，先呼叫确认）；
   - **危险区域内静止 → `danger`**（闯入后倒地的最坏情况，直接高危）。
3. **离线**：超过 `OFFLINE_THRESHOLD_SEC` 无信号 → warning 搜寻通报（标签没电/被破坏/进盲区），只播一次。
4. **重复广播只针对未确认的高危告警**，按 `ALARM_REPEAT_INTERVAL_SEC` 节奏；调度员确认后立即停止重复，但告警仍挂起直到现场消除——确认只代表"知道了"，不代表"没事了"。
5. **自动解除**：离开围栏 / 恢复移动 / 信号恢复，下一检测周期即解除并记录原因。
6. **进程重启后所有活动告警自动复位为已解除**（原因"系统重启"）：监控中断期间无法保证警情有效性，不允许悬挂的旧警情被当成现状。

## 广播渠道

- `console`：服务端控制台打印（生产环境替换为 IP 广播主机 SDK/CGI 调用，见 `src/broadcaster.js`）。
- `sse`：推送到所有调度大屏，浏览器用 Web Speech 播报到人、WebAudio 双音警笛（无需音频文件）。
- `webhook`：`POST {BROADCAST_WEBHOOK_URL}`，载荷含告警等级、标签、话术文本；超时 3s、失败重试 2 次，**外发失败不影响其他渠道与告警主流程**，失败记录可在大屏"广播记录"中看到。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量快照（人员、区域、告警、广播、UWB 统计） |
| GET | `/api/events` | SSE 实时事件流（snapshot/tick/alarm.*/broadcast.sent） |
| POST | `/api/positions` | HTTP 方式上报定位（字段同 UDP） |
| POST | `/api/alarms/ack` | `{alarmId, operator}` 确认告警，停止重复广播 |
| POST | `/api/alarms/clear` | `{alarmId, operator, reason}` 人工解除 |
| PATCH | `/api/zones/:id` | `{enabled:false}` 停用/启用围栏 |
| POST | `/api/sim/scenario` | 演练场景切换 `normal/intrusion/still` |
| POST | `/api/sim/force` | `{tagId,x,y}` 手动钉住标签位置（联动演练） |
| GET | `/readyz` | 存活探针 |

## 生产部署提示

- 同一坐标系：UWB 引擎、底图、围栏多边形必须一致；标定后再录入围栏顶点。
- 围栏顶点、人员档案目前通过 `src/defaults.js` 与管理接口维护，持久化于 `data/state.json`；多实例部署需替换为共享数据库（告警去重以"标签+类型+区域+active"为键，多实例会重复告警）。
- webhook 对接综合自动化平台时建议平台侧做幂等（携带 `alarmId`，重复广播 `repeat=true`）。
- 阈值按矿井制度调整：采掘工作面正常作业停顿可能超过 30s，静止阈值应结合岗位作业分析设置，避免告警疲劳。
